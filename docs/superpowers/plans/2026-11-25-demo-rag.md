# 데모 링크 RAG 열기 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 데모 링크 방문자 누구나 비슷한 콘텐츠 검색과 AI에게 물어보기를 실제로 쓰게 하고, 하루 사용량을 데모 전용 DB로 제한한다. 운영의 벡터 만들기는 관리자 게시물로 좁힌다.

**Architecture:** 데모(`NEXT_PUBLIC_DEMO_MODE=true`)는 DB 없이 예시 게시물을 코드에서 읽는다. 예시 게시물의 벡터는 미리 만들어 JSON 파일로 두고, 검색어와 질문만 실시간으로 Gemini에 보낸다. AI를 부르기 직전에 데모 전용 Supabase의 사용량 표에서 한 번의 SQL로 "상한 미만이면 1 올리기"를 하고, 실패하면 부르지 않는다.

**Tech Stack:** Next.js 16, `pg`(사용량 DB 연결, 이미 의존성에 있음), Gemini REST(`src/lib/ai/gemini.ts`), Node 테스트 러너.

**Spec:** `docs/superpowers/specs/2026-11-25-demo-rag-design.md`

## Global Constraints
- 데모 코드는 운영 DB에 연결하지 않는다. 사용량 DB 주소는 `DEMO_USAGE_DATABASE_URL` 하나만 쓴다.
- 하루 상한 기본값: 검색 300, AI에게 물어보기 60(AI 요청 단위, 질문 약 30개). 환경변수 `DEMO_LIMIT_SEARCH`, `DEMO_LIMIT_ASK`로 바꿀 수 있다.
- 상한 초과 안내 문구: `오늘 데모에서 쓸 수 있는 횟수를 다 썼어요. 내일 다시 써 주세요.`
- 날짜는 한국 시각(Asia/Seoul) 기준.
- 사용량 DB 연결 실패 = 상한 초과와 같게 처리(AI 부르지 않음).
- 예시 게시물 캡션은 새로 지어 쓴다. 실제 가게 이름, 계정 이름, 실제 캡션 금지.
- 운영의 벡터 만들기는 관리자(`AdminRole`) 게시물에만.
- 블로그 작업 로그: `~/Desktop/blog-drafts/blog-draft-trovely-rag-log.md`에 단계마다 한 줄.

## Review Focus
1. 동시에 여러 요청이 와도 상한을 넘겨 세지 않는다(한 번의 SQL로 올리기와 검사).
2. 사용량 DB가 없거나 연결이 안 될 때 AI를 부르지 않고 안내를 보인다.
3. 데모에서 운영용 서버 함수(가져오기, 저장, 관리자 화면)가 여전히 막혀 있다.
4. 예시 게시물 글을 고쳤는데 벡터 파일을 다시 만들지 않은 경우 테스트가 실패한다.
5. 운영에서 관리자가 아닌 가입자의 게시물은 벡터를 만들지 않는다(저장, 수정, 카테고리와 태그 변경, 채우기 스크립트 모두).

### Task 1: 하루 사용량 세기
**Interfaces (Produces):**
- `koreaDate(now: Date): string` — `YYYY-MM-DD`(Asia/Seoul)
- `demoLimit(kind: "search" | "ask"): number` — 환경변수 또는 기본값(300, 60)
- `consumeDemoQuota(kind): Promise<boolean>` — 상한 미만이면 1 올리고 true, 아니면 false. 연결 실패도 false.
- `DEMO_QUOTA_MESSAGE` 문구

- [ ] Step 1: `supabase/demo-usage.sql` 작성 — 표 `demo_usage(day date, kind text, count int, primary key(day, kind))`, 행 수준 보안 켜고 정책 없음(공개 API로 못 읽게).
- [ ] Step 2: 실패하는 테스트 — `koreaDate`(UTC 15:30 → 한국 다음 날), `demoLimit` 기본값과 환경변수.
- [ ] Step 3: 구현. `consumeDemoQuota`는 `INSERT … ON CONFLICT (day, kind) DO UPDATE SET count = demo_usage.count + 1 WHERE demo_usage.count < $limit RETURNING count` 한 번으로.
- [ ] Step 4: 로컬 DB에 같은 표를 만들어 `consumeDemoQuota`를 상한 3으로 5번 동시에 불러 true가 정확히 3번인지 확인(스크립트, 저장소 밖 임시 폴더).
- [ ] Step 5: 테스트 통과, 커밋.

1. **데모 전용 Supabase 프로젝트 만들기** (Task 1 전, 아무 때나)
   1. supabase.com 대시보드 → New project.
   2. 이름 `trovely-demo-usage`, 지역 Northeast Asia (Seoul), 요금제 Free.
   3. 데이터베이스 비밀번호는 생성 버튼으로 만들고 비밀번호 관리자에 저장한다(대화창에 붙여 넣지 않는다).
2. **사용량 표 만들기** (Task 1 커밋 뒤)
   1. 새 프로젝트 → SQL Editor → New query.
   2. 저장소의 `supabase/demo-usage.sql` 내용을 붙여 넣고 Run.
   3. Table Editor에 `demo_usage` 표가 생겼는지 확인.
3. **연결 주소 복사**: 프로젝트 → Connect → **Transaction pooler**(포트 6543) 주소. 비밀번호 칸을 실제 비밀번호로 바꾼 전체 주소를 준비한다.
