# AI 검색(비슷한 콘텐츠 찾기)을 모든 가입자에게 열기 설계

- 작성일: 2026-11-26
- 상태: 결정 6개 사용자 승인(2026-11-26, "모두 권장대로"). 설계 문서 검토 대기
- 앞선 문서: `2026-11-24-instagram-import-and-semantic-search-design.md`(뜻 검색), `2026-11-26-privacy-policy-and-withdrawal-design.md`(처리방침, 탈퇴)

## 1. 왜 하는가

지금은 관리자 게시물만 벡터(글의 뜻을 숫자로 바꾼 값)가 있어서, 일반 가입자는 키워드 검색만 쓸 수 있다. 일반 가입자도 "비슷한 콘텐츠 찾기"로 키워드에 걸리지 않은 게시물을 찾을 수 있게 연다. 다만 가입자의 글을 Google Gemini API로 보내야 하므로, 본인이 동의한 경우에만 보내고 언제든 철회할 수 있어야 한다.

## 2. 범위

**하는 것**
- 일반 가입자에게 "비슷한 콘텐츠 찾기"만 연다. 동의한 사람만 쓴다.
- 동의 안내 창, `/settings/ai` 설정 화면, 사이드바 메뉴, 공개 전 공지 띠.
- 동의 철회 시 Trovely에 저장된 AI 검색용 데이터(게시물 벡터, 검색어 벡터 캐시) 즉시 삭제.
- 가입자별, 서비스 전체 하루 사용량 상한.
- 비슷한 콘텐츠를 버튼을 누를 때 불러오기(관리자, 데모 포함).
- 처리방침 개정.

**하지 않는 것**
- 일반 가입자의 "AI에게 물어보기"(관리자와 데모만 유지).
- 일반 가입자의 메모, 후기 전송.
- 캐시를 쓰는 검색(같은 날 같은 검색어)의 반복 요청 제한.
- 동의 이력의 별도 보유기간 관리.
- 가입 연령 변경(만 14세 유지).

**실패로 보는 것(기능이 돌아가도 실패)**
- 동의하지 않은 사람의 글이나 검색어가 한 번이라도 Gemini로 가는 것.
- 철회한 뒤 Trovely에 그 사람의 벡터나 캐시가 남는 것.
- 남의 게시물이 결과에 섞이는 것.

## 3. 결정 사항(사용자 승인)

1. **만 18세:** Gemini API 약관(2026-03-23 시행)은 만 18세 미만이 쓸 가능성이 있는 서비스에서의 사용을 금지한다. 동의 창에서 "만 18세 이상" 확인을 받고, 체크하지 않으면 켜지지 않는다. 가입 연령은 14세 그대로. 공개 데모의 같은 문제는 따로 정한다.
2. **누를 때 불러오기:** 키워드 결과 수와 관계없이 "비슷한 콘텐츠 찾기" 버튼을 누를 때만 서버에서 불러온다. 버튼에 개수는 없다. 관리자와 데모도 같다. (2026-11-27 변경: 처음에는 키워드 결과가 0개면 화면을 그릴 때 바로 불러오기로 했으나, 같은 결과를 두 방식으로 보여 줘 헷갈리고 오타 검색에도 사용량이 빠져서 두 상황 모두 버튼으로 통일. 문구 "더 보기" → "찾기")
3. **동의 이력:** 계정이 있는 동안 남기고, 탈퇴하면 지운다.
4. **상한:** 검색어 벡터 가입자별 하루 30회, 전체 1,000회. 게시물 벡터 가입자별 하루 3,000개, 전체 10,000개. 설정값(상수)으로 둔다.
5. **공지:** 공개 7일 전부터 홈 위에 공지 띠. 법적으로 충분한지는 9번에서 확인.
6. **동의 문구:** 6번의 안을 쓴다. 9번 확인 뒤 최종 확정.

## 4. 누가 무엇을 쓰는가

| 사람 | 비슷한 콘텐츠 | AI에게 물어보기 | 보내는 글 |
|---|---|---|---|
| 관리자 | 동의 없이 사용 | 사용 | 카테고리, 태그, 캡션, 메모, 후기(지금과 같음) |
| 일반 가입자(동의, 공개 스위치 켜짐) | 사용 | 안 됨 | 카테고리, 태그, 캡션, 검색어 |
| 일반 가입자(그 밖) | 버튼만 보이고 누르면 동의 창 | 안 됨 | 없음 |
| 데모 방문자 | 지금과 같음(예시 데이터) | 지금과 같음 | 예시 데이터 |

판단 함수는 하나만 둔다: `canUseAiSearch(userId)` = 관리자이거나, (`AI_SEARCH_PUBLIC`이 켜져 있고 동의 상태가 켜져 있음). 서버 함수, 벡터 생성, 화면이 모두 이 함수를 쓴다. 화면에서 숨기는 것만으로 막지 않는다.

## 5. 데이터(새 표 5개, 기존 표는 안 바꿈)

| 표 | 칸 | 용도 |
|---|---|---|
| `AiSearchConsent` | `userId`(기본 키), `enabled`, `policyVersion`, `generation`(작업 버전 숫자), `consentedAt`, `revokedAt` | 현재 상태 |
| `AiSearchConsentLog` | `id`, `userId`, `action`(consent/revoke), `policyVersion`, `createdAt` | 이력 |
| `QueryEmbeddingCache` | `userId`, `day`(한국 날짜), `model`, `textHash`, `embedding`(만드는 중이면 비어 있음), `createdAt`. 기본 키(userId, day, model, textHash) | 같은 날 같은 검색어 재사용. 검색어 원문은 저장 안 함 |
| `AiUsageUser` | `userId`, `day`, `kind`(query/document), `count`. 기본 키(userId, day, kind) | 가입자별 상한 |
| `AiUsageTotal` | `day`, `kind`, `count`. 기본 키(day, kind) | 전체 상한 |

- 모두 운영 DB에 둔다. 공개 API(Supabase anon 키)로 읽고 쓰지 못하게 RLS(행 단위 접근 제한)를 켠다. 기존 표와 같은 방식.
- 지난 날짜의 캐시 줄은 검색할 때 그 사람 것을 함께 지운다.
- 철회해도 사용량 줄은 지우지 않는다(철회, 재동의로 상한을 우회하지 못하게).

## 6. 동작

### 6.1 동의 켜기
1. 서버가 만 18세 확인과 처리방침 버전을 받는다. 확인이 없으면 거절.
2. 한 번의 DB 처리(트랜잭션) 안에서: 동의 상태를 켜고 `generation`을 1 올리고, 이력 한 줄을 남긴다.
3. 응답 뒤(`after`)에 그 사람 게시물 벡터 만들기를 시작한다(6.4).

### 6.2 철회
한 번의 DB 처리 안에서: 동의 상태 줄을 잠그고 끄며 `generation`을 1 올림 → 그 사람의 `ReelEmbedding` 삭제 → 그 사람의 `QueryEmbeddingCache` 삭제 → 이력 한 줄. 하나라도 실패하면 모두 되돌리고 화면에 오류를 보여 준다. 원본 게시물과 사용량 줄은 그대로.

### 6.3 벡터 저장과 철회가 겹칠 때
- 벡터 작업은 시작할 때 `generation`을 기억한다. Gemini에 보내기 직전(100개 묶음마다) 동의가 켜져 있고 `generation`이 같은지 다시 본다. 다르면 멈춘다.
- 저장은 문장 하나로 한다: 동의 상태 줄이 켜져 있고 `generation`이 같을 때만 넣는다. 이때 그 줄에 읽기 잠금(`FOR SHARE`)을 건다. 철회는 그 줄을 바꾸므로 저장이 끝날 때까지 기다렸다가 진행되고, 같은 처리 안에서 벡터를 지우므로 방금 들어간 벡터도 지워진다.
- 관리자는 이 확인을 건너뛴다.
- 게시물 하나 저장이 실패해도(게시물이 그사이 지워짐 등) 나머지는 계속한다.

### 6.4 게시물 벡터 만들기(일반 가입자)
- `upsertReelEmbeddings`의 "관리자만" 확인을 "게시물 주인이 `canUseAiSearch`"로 바꾼다. 부르는 곳 9군데는 그대로.
- 일반 가입자 글에서는 메모와 후기를 뺀다(`buildEmbeddingText`에 선택값 추가).
- 해시가 같으면 건너뛴다(지금과 같음). 그래서 다시 시도하면 남은 것만 처리된다.
- Gemini 요청 전에 가입자별, 전체 하루 상한에서 개수만큼 뺀다. 모자라면 남은 만큼만 처리하고 멈춘다.
- 켤 때, 그리고 처음 보는 검색어로 검색할 때(하루 최대 30번) 응답 뒤에 그 사람 게시물 전체를 100개씩 처리하고, 200초가 지나면 멈춘다(Vercel Hobby 함수 최대 300초). 이미 만든 게시물은 건너뛰므로 평소에는 보내는 게 없다. 처음 켤 때 일부가 실패해도 다음 검색 때 이어서 만든다(2026-11-27 변경: 설정 화면의 "다시 시도" 대신).

### 6.5 비슷한 콘텐츠 찾기(`getSimilarReels`)
순서: 로그인 확인 → `canUseAiSearch` → 검색어 벡터 캐시 확인 → 없으면 상한 확인 후 Gemini → 그 사람 게시물에서만 검색.
- 캐시: (userId, 오늘, 모델, 해시)로 "만드는 중" 줄을 먼저 넣는다. 넣는 데 성공한 요청만 사용량을 빼고 Gemini를 부른다. 실패하면 그 줄을 지운다. 나머지 요청은 최대 3초 기다렸다가 벡터가 생기면 쓰고, 없으면 빈 결과(키워드 결과만 보임).
- 사용량: 데모와 같은 방식("상한보다 작을 때만 1 올리기"를 문장 하나로)을 가입자별, 전체에 각각. 하나라도 실패하거나 DB 오류면 Gemini를 부르지 않는다.
- 쓸 수 없는 사람은 `{ items: [], needsConsent: true }`를 돌려준다. 화면은 이 값을 보고 동의 창을 띄운다.

### 6.6 탈퇴
`deleteAccountData`의 한 묶음 처리에 새 표 5개 중 사용량 전체 표를 뺀 4개(동의 상태, 이력, 캐시, 가입자별 사용량)의 그 사람 줄 삭제를 더한다. `ReelEmbedding`은 게시물 삭제와 함께 지워진다(외래키 cascade).

### 6.7 공개 스위치
서버 전용 환경변수 `AI_SEARCH_PUBLIC`. 꺼져 있으면 `canUseAiSearch`가 일반 가입자에게 항상 거짓이고, 설정 메뉴와 공지 띠도 안 보인다. 켜는 것은 사용자가 Vercel에서 한다.

## 7. 화면과 문구

- **동의 안 한 사람:** 키워드 결과 아래 "비슷한 콘텐츠 찾기" 버튼. 누르면 아래에서 동의 창이 올라온다(AI에게 물어보기 창과 같은 모양). 닫으면 그대로.
- **키워드 결과 0개:** 검색어만으로 검색했으면 돋보기 아이콘과 "검색어가 포함된 콘텐츠가 없습니다.", 카테고리나 출처도 골랐으면 "조건에 맞는 콘텐츠가 없습니다". 그 아래 같은 버튼.
- **동의한 사람:** 누르면 "찾는 중..." 뒤 버튼 자리에 결과가 펼쳐진다. 없으면 "비슷한 콘텐츠가 없습니다". 하루 상한을 넘으면 데모 문구와 같은 방식으로 알린다.
- **`/settings/ai`:** 켜기/끄기 스위치와 처리방침 링크만. 게시물 준비 상태와 "다시 시도", 켤 때 안내 문구는 보여 주지 않는다(사용자는 켜졌는지만 알면 된다, 2026-11-27 사용자 결정). 끌 때는 "AI 검색을 껐어요. AI 검색용 데이터를 삭제했어요."를 보여 준다(데이터 삭제 확인).
- **사이드바:** "AI 검색 설정" 메뉴(공개 스위치가 켜졌을 때만).
- **공지 띠:** 홈 위. 닫으면 그 기기에서는 다시 안 보임(브라우저 저장소).

동의 창 문구:

> 검색어와 의미가 비슷한 게시물도 찾아보세요.
> AI 검색을 위해 게시물의 카테고리, 태그, 캡션과 검색어를 Google Gemini API로 전달해요. 직접 작성한 메모와 후기, 이메일, 로그인 정보는 전달하지 않아요.
> Google은 전달받은 내용을 AI 학습에 쓰지 않지만, 남용 방지를 위해 최대 55일 동안 보관할 수 있어요. 처리 과정에서 해외에 있는 Google 시설을 거칠 수 있어요.
> AI 검색은 선택 기능이에요. 동의하지 않아도 기존 기능을 그대로 쓸 수 있어요.
> AI 검색 설정에서 언제든 사용을 중단할 수 있어요. 중단하면 Trovely에 저장된 AI 검색용 데이터는 바로 삭제돼요. 이미 Google에 전달된 내용은 위 보관 기간에 따라 처리돼요.
> - [ ] 만 18세 이상이며, AI 검색을 위한 정보 처리 안내를 확인하고 동의합니다.
> - 버튼: 동의하고 사용하기 / 나중에 할게요

## 8. 공개 순서

1. 공개 스위치를 끈 채로 코드 배포(DB 이전 포함). 관리자, 데모만 바뀐다(누를 때 불러오기).
2. 사용자가 9번 확인을 마치고 동의 문구, 처리방침 문구 확정.
3. 처리방침 개정 배포, 공지 띠 시작.
4. 7일 뒤 사용자가 Vercel에서 `AI_SEARCH_PUBLIC`을 켠다.

## 9. 공개 전 사용자가 확인할 것(코드 작업을 막지 않음)

1. 개인정보 보호법 제28조의8: 동의를 근거로 쓸 때 제2항의 알릴 사항(이전 항목, 국가, 시기와 방법, 받는 자와 연락처, 목적과 보유 기간, 거부 방법)을 동의 창에 다 넣어야 하는지. 국가법령정보센터 원문, 개인정보보호위원회 처리방침 작성지침, 118 상담.
2. 이전받는 자의 정확한 법인명과 연락처(Google Cloud 결제 계정의 계약 법인).
3. 앱 안 공지만으로 처리방침 변경 고지가 충분한지.
4. 동의 기록을 탈퇴 뒤에도 보관해야 하는지.

## 10. 테스트

- 동의 안 한 사람: 서버 함수 직접 호출, 게시물 저장과 수정 → 가짜 Gemini 호출 수 0.
- 일반 가입자 글에 메모, 후기 없음.
- 다른 계정의 게시물, 캐시가 결과에 안 나옴.
- 일반 가입자의 AI에게 물어보기 직접 호출 → 거절(기존 유지).
- 생성 중 철회: 가짜 Gemini를 일부러 늦춰 순서 재현 → 남은 벡터 0.
- 철회 후 재동의, 탈퇴, 게시물 수정과 삭제 뒤 벡터 상태.
- 벡터 삭제 실패 → 철회도 되돌려짐.
- 중단 후 다시 시도 → 남은 것만 보냄.
- 같은 검색어 동시 5번 → Gemini 1번, 사용량 1.
- 상한을 작게 두고 동시 요청 → 정확히 상한까지.
- 사용량 DB 오류 → Gemini 0번, 키워드 결과 정상.
- 철회 후 재동의해도 그날 사용량 유지.
- 카테고리 다중 선택, 출처 탭과 함께 쓸 때 조건 안에서만.
- 관리자 AI 기능, 데모 화면이 지금과 같음(누를 때 불러오기 제외).
- 공개 스위치 꺼짐 → 버튼, 메뉴가 안 보이고 서버 함수 직접 호출도 거절.
- 만 18세 확인 없이 켜기 → 거절.

## 11. 남는 한계

- 게시물을 빠르게 두 번 고치면 먼저 시작한 작업이 나중에 끝나 옛 글의 벡터가 남을 수 있다. 다음 수정이나 다시 시도 때 해시가 달라 다시 만들어진다(관리자 쪽에도 지금 있는 문제).
- 철회 전에 이미 Gemini로 보낸 데이터는 되돌릴 수 없다(Google 55일 보관). 동의 문구에 적는다.
- 응답 뒤 작업(`after`)이 300초 안에 포함되는지는 문서로 확인하지 못했다. 200초에서 스스로 멈춘다.
